# 페이지를 안 바꾸고 데이터만 받으려면

책을 읽다가 이런 코드를 만났다. 처음 보는 사람에게는 꽤 낯선 모양새다.

```javascript
const xhr = new XMLHttpRequest();
xhr.open('GET', '/todos');
xhr.send();

xhr.onload = () => {
  if (xhr.status === 200) {
    console.log(JSON.parse(xhr.response));
  }
};
```

`fetch` 한 줄이면 될 일을 왜 이렇게 쓰나 싶었는데, 사실 순서가 반대였다. **이 낯선 객체가 없었다면 fetch도, SPA도, 지금의 웹 자체가 없었다.** 이름의 XML부터 이벤트 기반 문법까지, 이 코드에는 웹이 문서에서 애플리케이션으로 넘어온 역사가 눌러 담겨 있다.

## 전통 방식 — 모든 클릭은 페이지 전체를 다시 받는 일이었다

초기 웹에서 서버와의 상호작용은 단 한 가지였다. 링크를 클릭하거나 폼을 제출하면, 브라우저는 **완전한 HTML 문서를 새로 받아 화면 전체를 처음부터 다시 렌더링**했다. 장바구니에 물건 하나를 담아도 페이지 전체가 깜빡이며 다시 그려진다. 바뀐 건 화면 구석의 숫자 하나인데, 변경이 필요 없는 나머지 전부까지 다시 받아오는 것이다 — 전송량도 낭비고, 렌더링을 다시 하는 동안 화면이 순간적으로 끊기는 경험도 피할 수 없었다.

이 구조를 깬 것이 **Ajax**(Asynchronous JavaScript and XML)다. 브라우저가 제공하는 `XMLHttpRequest` 객체로 **자바스크립트가 직접, 비동기로** 서버와 통신하는 방식이다. 페이지 전환 없이 필요한 데이터만 받아서, 바뀌어야 할 부분의 DOM만 갈아 끼운다. 2005년 구글 맵스가 이 방식으로 "드래그하면 지도가 끊김 없이 이어지는" 경험을 보여주면서 웹 전체의 방향이 바뀌었다.


이름에 XML이 박혀 있는 건 그 시절의 데이터 교환 형식이 XML이었기 때문이다. 지금은 더 가볍고 자바스크립트 객체와 문법이 거의 같은 **JSON**이 표준이 됐다. 언어 독립적인 텍스트 포맷이라 어떤 서버와도 통하고, `JSON.stringify`(객체→문자열, 직렬화)와 `JSON.parse`(문자열→객체)로 변환도 한 쌍이다. 이름과 실체가 어긋난 채 남은 것이다 — 다들 그냥 "Ajax"라고 부르지만 XML을 쓰는 경우는 이제 거의 없다.
