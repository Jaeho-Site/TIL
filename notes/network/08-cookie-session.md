# 무상태인데 로그인은 어떻게 유지되나

[HTTP 메시지 편](/network/05-http-message)에서 서버는 요청이 끝나면 나를 기억하지 않는다고 했다. 그런데 현실의 나는 아침에 로그인한 사이트를 저녁까지 잘 쓰고 있다. 공부하다 이 지점을 파면서 스스로 문제를 하나 만들어봤다.

> 로그인 성공 직후, 서버가 보낸 응답 헤더에는 무엇이 들어 있을까? 그리고 그다음 요청부터 브라우저가 하는 일은?

핵심은 **기억의 주체를 바꾸는 것**이다. 서버가 나를 기억하는 게 아니라, **내가 서버에게 나를 증명할 것을 매번 들고 다닌다.**

## 쿠키 — 매 요청에 따라붙는 메모

로그인 성공 응답에는 이런 헤더가 실려 온다.

```
HTTP/1.1 200 OK
Set-Cookie: sessionId=abc123; Path=/; HttpOnly; Secure; SameSite=Lax
```

브라우저는 `Set-Cookie`를 받으면 그 값을 저장해 두고, **같은 사이트로 가는 모든 후속 요청에 자동으로 붙인다.**

```
GET /mypage HTTP/1.1
Cookie: sessionId=abc123
```

이게 쿠키의 전부다 — 서버가 "다음에 올 때 이 쪽지를 보여달라"고 건네준 메모를, 브라우저가 성실하게 매번 제시하는 것. HTTP 자체는 여전히 무상태다. 프로토콜을 고친 게 아니라, **헤더 위에 상태를 얹는 관례**를 만든 것이다.
