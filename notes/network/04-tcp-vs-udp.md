# UDP는 결함이 아니라 선택이다

다음 중 UDP를 쓰는 통신은 무엇일까?

1. DNS 조회
2. 유튜브 실시간 스트리밍
3. HTTP/3
4. 이메일 전송

답은 **1, 2, 3**이다. 나는 처음 공부할 때 UDP를 "TCP에서 기능을 뺀 열화판"으로 이해했어서, 최신 프로토콜인 HTTP/3가 UDP 위에서 돈다는 게 이상하게 느껴졌었다. 낡은 게 아니라 오히려 최전선에 있는 이유 — 그게 이 글의 주제다.

## 갈라지는 지점은 "얼마나 책임질 것인가"

[계층 모델](/network/01-layered-model)에서 봤듯 전송 계층의 역할은 **프로세스와 프로세스 사이의 통신**이다. IP가 호스트까지 데이터를 옮기면, 전송 계층은 포트 번호로 그 호스트의 어떤 애플리케이션에 전달할지를 정한다. 여기까지는 TCP와 UDP가 같다. 갈라지는 지점은 **전달을 얼마나 책임질 것인가**이다.

TCP는 최대한 책임지는 쪽을 택했다. 지난 두 글에서 본 그대로다.

- **연결 지향**: 보내기 전에 [세 번의 인사](/network/02-tcp-handshake)로 연결을 수립한다
- **신뢰성**: 세그먼트마다 순서 번호를 붙이고, ACK가 없으면 재전송한다
- **순서 보장**: 뒤섞여 도착해도 순서 번호로 재조립한다
- **속도 조절**: [받는 쪽과 길의 사정](/network/03-flow-congestion)에 맞춰 전송량을 조절한다

UDP는 반대로 거의 아무것도 책임지지 않는다. 포트 번호로 전달하고, 체크섬으로 깨졌는지 확인하는 정도가 전부다. 연결 수립도, 재전송도, 순서 보장도, 속도 조절도 없다. 헤더 크기부터 다르다 — TCP 헤더가 기본 20바이트인데 UDP 헤더는 8바이트다.

| | TCP | UDP |
|---|---|---|
| 연결 | 연결 지향 (3-way 핸드셰이크) | 비연결 — 그냥 보낸다 |
| 신뢰성 | ACK와 재전송으로 보장 | 보장 없음 (체크섬만) |
| 순서 | 순서 번호로 재조립 | 보장 없음 |
| 속도 조절 | 흐름 제어 + 혼잡 제어 | 없음 |
| 헤더 | 기본 20바이트 | 8바이트 |
| 전송 단위 | 세그먼트 (스트림 분할) | 데이터그램 (메시지 단위) |
| 대표 용도 | 웹(HTTP/1.1·2), 파일 전송, 이메일 | DNS, 스트리밍, 게임, QUIC |
