# Network

네트워크를 공부하며 생긴 궁금증을 하나씩 해결해 나간 기록입니다.

특정 교재 없이 AI와 블로그, MDN·RFC 같은 공식 문서를 오가며 공부했고, 그 과정을 [블로그에 시리즈](https://ezilog.dev)로 정리하기도 했습니다. 이 노트는 그때 공부한 내용을 처음 궁금해했던 질문의 순서대로 다시 엮은 것입니다.

네트워크는 브라우저 개발자 도구의 Network 탭에서 매일 마주치지만, 그 안에서 실제로 무슨 일이 일어나는지는 의외로 설명하기 어렵습니다. 요청 한 번이 어떤 계층을 지나고, 어떤 약속으로 오가며, 왜 이런 모습으로 진화했는지 — 그 'Why'를 따라가며 정리했습니다.

## 질문 지도

```
브라우저와 서버 사이에는 정확히 무엇이 오가는 걸까?
└─ 계층을 나눈 건 알겠는데, 연결은 어떻게 시작될까?
   └─ TCP는 연결을 왜 세 번 주고받으며 시작할까?
      └─ 연결됐으면 그냥 최대한 빨리 보내면 되는 거 아닌가?
         └─ 그 노력을 전부 포기한 UDP는 왜 아직도 쓰일까?

HTTP 메시지 안에는 실제로 뭐가 들어 있을까?
└─ GET과 POST는 정말 "조회와 생성"의 차이뿐일까?
└─ HTTP는 왜 버전을 세 번이나 갈아엎었을까?

서버는 나를 기억하지 않는다는데, 로그인은 어떻게 유지되지?
두 번째 방문은 왜 첫 방문보다 빠를까?

HTTPS의 자물쇠는 실제로 무엇을 보장할까?
분명 서버는 살아있는데, 브라우저는 왜 내 fetch를 막을까?

주소창의 도메인은 어느 시점에 IP가 될까?

페이지를 새로 받지 않고 데이터만 받을 수는 없을까?
└─ 그 API의 주소와 메서드는 어떤 약속으로 정할까?
   └─ 반대로 서버가 먼저 브라우저에게 말을 걸 수는 없을까?

그래서, URL을 입력하고 화면이 뜨기까지 — 전부 이으면 어떤 그림일까?
```
